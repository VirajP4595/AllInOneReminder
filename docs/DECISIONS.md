# Decision log

Format: `YYYY-MM-DD — Decision — Reason — Alternatives considered`

- 2026-11-04 — Native Kotlin + Jetpack Compose — The alarm and lock-screen path is native; a cross-platform layer adds risk there — Flutter, React Native
- 2026-11-04 — Local-first; each device schedules its own alarms — Reminders must ring offline; push delivery is unreliable on OEM ROMs — Server-driven push alarms
- 2026-11-04 — Backend for Phase 2: Supabase free + FCM only, end-to-end encrypted — $0 with no card; server can't read health data — Firebase Blaze (needs a card), self-hosted, local-only
- 2026-11-04 — Missed-dose check runs on the server — A dead or offline patient phone cannot report its own miss — Patient-device-only escalation
- 2026-11-04 — Escalation grace 60 min default, per item override — Owner choice; shorter for insulin-type items — Single global value
- 2026-11-04 — Any household member can edit, with change log + change alerts + 30-day undo — Owner choice; safeguards against silent dose changes — Admin-only editing
- 2026-11-04 — Gamification rewards on-time habits; meds earn points only inside their window — Avoid rewarding late or double doses — Uniform gamification
- 2026-11-04 — Encrypted DB means alarms resume only after first unlock after reboot — Do not store medicine data in device-protected storage — Direct-boot-aware storage
- 2026-11-04 — Destructive migrations disabled; all future schema upgrades require explicit Migration and MigrationTestHelper tests — Prevents accidental silent wipe of patient medications, doses, and history on app updates — Fallback to destructive migration
- 2026-11-04 — android:allowBackup="false" with full backup exclusions — Prevents Android Cloud Backup from copying encrypted DB without KeyStore master key, which causes unrecoverable crash on new device — Cloud backup enabled
- 2026-11-04 — net.zetetic:sqlcipher-android:4.6.1 with 16 KB page-size support and SupportOpenHelperFactory — Replaces deprecated android-database-sqlcipher 4.5.4 to support modern Android 15+ 16 KB page size architecture — Legacy sqlcipher
- 2026-11-04 — Profile soft-deletion cascades to items and schedules in transaction — Prevents orphaned medicine alarms from continuing to ring after profile deletion — Profile-only soft delete
- 2026-11-04 — Foreground service type `mediaPlayback` for `AlarmRingService` — On Android 14+ (API 34+), foreground services must declare a specific type; mediaPlayback matches continuous alarm audio and vibration playback, with specialUse declared in manifest as companion — specialUse only, systemExempted
- 2026-11-04 — Single `setAlarmClock` registration with `AlarmCoordinator` idempotency — setAlarmClock bypasses Doze mode and gives highest priority to ring on locked screens without battery saver delays — Periodic background workers, setExactAndAllowWhileIdle
- 2026-11-04 — Grace calculation uses `maxOf(plannedAt, dueAt) + graceMinutes` for all unresolved statuses, and re-planning unresolved rows updates both `plannedAt` and `dueAt` — Prevents active meal deferrals, snoozes past plannedAt+grace, and timezone shifts from prematurely expiring as MISSED — Strict `plannedAt + graceMinutes`
- 2026-11-04 — Exact alarm permission safety: declare USE_EXACT_ALARM on API 33+, SCHEDULE_EXACT_ALARM with maxSdkVersion="32", check canScheduleExactAlarms(), catch SecurityException, fall back to setExactAndAllowWhileIdle then setAndAllowWhileIdle, show persistent red banner on Today — Prevents SecurityException crash on Android 14+ when exact alarms are revoked — Crashing or silent failure
- 2026-11-04 — Notification "Take" action routes as PendingIntent.getActivity to `AlarmActivity` — Complies with Android 12+ notification trampoline restriction (blocking background receivers from starting activities) and reliably triggers double-dose warning dialog when within minGapMinutes — Background broadcast trampoline
- 2026-11-04 — Encrypted Backup uses AES-256-GCM + PBKDF2-HMAC-SHA256 (310,000 iterations) with ZIP archive containing DB JSON and photos, with 50MB payload cap — Conforms to §17 spec for encrypted offline backup and restore, authenticates backup integrity with GCM AEAD tag without leaking health data, and caps memory consumption to avoid OOM on budget phones — Plain zip, AES-CBC with HMAC-SHA256, uncapped memory streaming
- 2026-11-04 — Backup restore safety: Zip Slip prevention (reject names with /, \, .. and assert canonical path), DataInputStream.readFully for SAF streams, temporary directory extraction before database transaction, and relative filesDir photo paths — Prevents arbitrary file write exploits, SAF chunk truncation errors, and path mismatches across devices — In-place extraction
- 2026-11-04 — Release signing falls back to debug keystore when signing secrets are absent, producing `app-<version>-debugsigned.apk` — Distinguishes unsigned/debug builds from official production releases and alerts users that uninstall is required before installing production builds — Hardcoded test keystore, naming debug builds app-release.apk
- 2026-11-04 - R8 code and resource shrinking enabled in release builds with keep rules for Room, Hilt, SQLCipher, and Coroutines - Shrinks APK footprint significantly and protects against reverse engineering without breaking reflection/native JNI bindings - Unminified release builds
- 2026-11-06 - "Specific days" reuses `EVERY_N_WEEKS` with `intervalN = 1` and the `weekdayMask` instead of adding a separate weekly type - The engine already implements the mask semantics, so one recurrence path stays tested and stable - New `SPECIFIC_WEEKDAYS` enum value
- 2026-11-06 - `MONTHLY` supports either `dayOfMonth` (1-31, clamped to the month length) or `nthWeek` (1-4, 5 = last) plus a single weekday bit - Covers "every 15th" and "second Tuesday" with the existing weekday-mask convention - Separate FIRST/SECOND/... recurrence types
- 2026-11-06 - `INTERVAL` produces multiple fixed-time doses per day from `windowStartMinute` to `windowEndMinute` in `intervalHours` steps, using the existing `toSafeInstant` DST guard - Keeps every planned dose as its own deterministic occurrence id and handles spring-forward gaps - Single dose per day, relative-only intervals
- 2026-11-06 - `PRN` schedules are skipped by the planner; "Take now" in Today inserts a `TAKEN` occurrence with a random UUID and `plannedAt = dueAt = remindAt = actedAt = now` - As-needed medicines have no predictable times, and history needs a real dated row - Pre-generating placeholder occurrences
- 2026-11-06 - Taper steps are modeled as per-schedule `validFrom`/`validUntil` plus `doseAmountOverride`, resolved through `effectiveDoseAmount(schedule, item)` - One item keeps one history while each taper step carries its own dates and dose - Duplicating items per step
- 2026-11-06 - Room schema v3 adds only nullable columns (`item.maxPerDay`, eight schedule fields) with `ALTER TABLE ... ADD COLUMN` and no defaults, registered as `MIGRATION_2_3` - Existing rows stay valid and no destructive migration is needed - Rebuilding tables
- 2026-11-06 - Stock ledger modeled as append-only `stock_event` table with deterministic UUIDs for TAKEN events (`UuidV5.generate(OCCURRENCE_NAMESPACE, "stock_$occurrenceId")`) - Prevents duplicate decrements on network or retried take actions, keeps full audit trail, and computes current balance dynamically via `SUM(delta)` - Mutable `stock` column on item
- 2026-11-06 - Stock tracking enabled only for items with at least one event in `stock_event` - Preserves legacy behavior for untracked medicines where stock should not display and refill alerts should not fire - Boolean `trackStock` column on item
- 2026-11-06 - Refill alerts rate-limited per-item to at most once per calendar day via DataStore - Avoids alert fatigue when multiple doses are taken in rapid succession on the same day when stock is below threshold - Unlimited alerts on every take
- 2026-11-06 - Low stock threshold triggers when balance <= `refillThreshold` or remaining days of supply <= 5 (computed via 14-day planned schedule counts) - Gives patients sufficient advance notice to request pharmacy refills - Fixed count threshold only
- 2026-11-06 - Cease writing new unit/integration tests; focus purely on feature implementation, compilation, schema migrations, and manual device verification - User instruction to accelerate feature velocity - Maintaining test-first / comprehensive unit test suite
